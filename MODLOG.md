## 0.3.5 Godot 4 skeleton pose correction

Found a real rig error affecting villagers, creatures, advisers and animated landmarks: `L3dRig.apply_local_pose` subtracted each bone's rest transform before setting its pose. Godot 4 uses parent-local poses that already include the rest transform, unlike Godot 3. The original ANM and CBN readers produce parent-local poses, so subtracting rest distorted the actual engine skeleton. Additionally, newly loaded rigs had no explicit rest pose until animated. The rig now initializes the bone pose from its original rest and assigns the animation's parent-local transform directly, preserving signed scale. Reference: Godot's own skeleton documentation, https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html.

Added a headless regression test that compares the actual Godot skeleton's local and hierarchical bone transforms to the decoded originals, including idle hands below shoulders. Before the fix, 37 checks failed; afterwards 46 passed across all eight villager types, three creature types and both advisers. Some original rest matrices contain slight shear, which Godot's rotation/scale representation approximates, so the rest-pose test allows a bounded tolerance; animated poses use tighter thresholds. Existing suites also passed: 199 port, 72 story, 15 landmark and 42 audio checks. These are not rendered gameplay or a first-island playthrough; visual verification and a new Melty installation test remain pending.

Continued tracing the original first-island influence calls in the installed executable. Their effects still depend on world and player systems the prototype does not implement. The campaign remains disabled and those calls continue to block rather than silently pretending to work.
