# Сверка с запущенным оригиналом

17 ноября 2026 пользователь потребовал сравнивать оригинал и Godot кадр в кадр.
Это обязательная часть дальнейшей реставрации. Зелёные unit/scene tests не
подтверждают визуальное соответствие. Preview9.6 остаётся обычной сборкой;
незавершённый кандидат9.7 не активирован.

## Как сравнивать

1. Запустить установленный оригинал в отдельном тестовом профиле. Перед этим
   сохранить Profiles и изменяемые настройки вне Git. Записать SHA256 exe,
   версию compatibility wrapper, его конфигурацию и разрешение клиента.
2. Запустить Godot в таком же разрешении и соотношении сторон. Для исходной
   установки сейчас получен клиент800x600. Не растягивать16:9 до4:3. Для
   проверки исходной композиции отключить улучшения, меняющие картинку.
3. Совместить **событие сюжета и фазу реплики/анимации**, затем сравнивать кадры.
   Одинаковое число секунд после запуска не обеспечивает совпадения: загрузка,
   пропуск видео, ввод и симуляция двух движков различаются. Точный общий clock,
   воспроизводимый ввод оригинала и синхронная видеозапись пока не реализованы.
4. Сохранить PNG/метаданные только в игнорируемой scratch/build либо приватной
   Reference. У Godot verify_opening_runtime сохраняет рядом с PNG JSON: viewport,
   камеру/FOV, номер кадра, elapsed, time_scale, source script/pc, fade и media mode.
   Это координаты Godot, а не автоматически измеренная камера оригинала.
   Godot может убрать --main-pack из доступных скрипту аргументов: пустой
   main_pack/hash не доказывает источник. Команду запуска и SHA256 export
   дополнительно записывать в manifest набора кадров.
5. Получить пару, наложение и карту различий:

   ```powershell
   python tools/compare_frames.py `
     --reference 'C:/local-reference/original.png' `
     --candidate 'C:/local-reference/godot.png' `
     --event 'intro-father-first-cry' `
     --out-dir 'scratch/visual-reference/intro-father'
   ```

   Требуется Pillow. Если снимок содержит рамку окна, её можно убрать явно
   параметром --reference-crop/--candidate-crop x,y,width,height. Других
   автоматических преобразований нет: несовпадение размера отклоняется.
   JSON-метаданные прилагаются через --reference-meta/--candidate-meta.
6. Проверить пару визуально и записать конкретное расхождение в BUGS_RU.md.
   Числовые MAE/проценты отличаются даже при корректной смене освещения и
   рендера; инструмент **не выдаёт PASS** и не доказывает точность механик.
   Не выравнивать картинки по объектам: это скроет ошибку камеры.

## Сцены для первого прохода

| Событие | Что проверять |
| --- | --- |
| Паника отца и ребёнок в море | Положение/наклон камеры, поверхность воды, опора людей |
| Акулы | Высота камеры над водой, глубина/отражения, положение акул |

| Роща и выбор существа | Размеры, bind pose, исходные клипы, ворота, переход домой |

  https://github.com/dege-diosg/dgVoodoo2/releases/tag/2.87.6.

  Ни изменённый windowed config, ни default config не дали targetable окна.

  папку. Это не работающая эталонная конфигурация, не оставлять как установленный fix.
- Штатный Setup.exe вызвал UAC. Ввод через Computer Use остановлен на время
  запроса; системные разрешения/защита не менялись. Запрос отменён пользователем,
  что подтверждено результатом Start-Process. Не запускать Setup.exe повторно вслепую.
- Вторая проба DDrawCompat0.7.1 подготовлена локально. Официальный ZIP SHA256
  0C33ECB1C01C1C779063B490A2E818F6D9227B3B4EE827C51790FB0FD59B17C5.

  DDrawCompat не установлен в оригинал. Не повторять отклонённую команду обходным путём.
- compare_frames.py проверен синтетическими кадрами: идентичные дают0,
  изменение100 пикселей учитывается точно, различие размеров отклоняется.

## Последующие штатные проверки

Пользователь сообщил, что Setup не открывается. Без wrapper/элевации проверен
неизменённый original exe с правильным cwd: растянутые треугольники сохранились.
Ghidra read-only исследование нашло реальные BWSetup/HardwareTnL/FullScreen.
Temporary per-user FullScreen0 действительно создал обычное окно; отдельно
HardwareTnL1 в fullscreen после reactivation показал чёрное поле, и этот тест
не отделяет renderer от surface-loss. Windowed с HardwareTnL1 и0 дал искажённую
геометрию и не подходит для fidelity baseline. Снимки сохранены приватно.

В штатном меню Options наблюдаются Fullscreen, FPS, Dump Bitmap, Log Properties
и Pause. Попытка Dump Bitmap не дала найденного нового BMP/TGA в папке игры;
успешная запись framebuffer не подтверждена. Screenshot оконного клиента
содержит рамки/DPI-преобразование; автоматически считать его800x600 нельзя.
Все свои original процессы остановлены, HardwareTnL/FullScreen восстановлены
к исходно отсутствующим значениям. Системная защита/драйверы не менялись.
